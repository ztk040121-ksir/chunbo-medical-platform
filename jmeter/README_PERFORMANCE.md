# 春播云诊所 - AI 问诊接口性能压测与优化总结报告

## 一、 测试背景与目标
针对基层医疗云诊所早高峰集中接诊场景（8:30 - 10:00），评估 AI 问诊智能体在多医生并发会话下的性能瓶颈与稳定性表现。

- **压测接口**：
  1. `GET /api/patients`（就诊患者档案列表，REST）
  2. `GET /api/medical/chat/stream`（AI 问诊 SSE 流式生成接口，伴随 Tool Calling）
- **压测工具**：Apache JMeter 5.6.3
- **压测策略**：阶梯加压（50 并发 -> 100 并发 -> 200 并发），梯度持续加压 120 秒。

## 三、 面试官高频提问与优化落地策略 (简历业绩支撑)

### 1. 针对 SSE 长连接对服务端连接池的消耗，如何做资源隔离？
- **落地手段**：引入 Spring WebFlux 反应式非阻塞模型，利用 Project Reactor 的 `Flux<String>` 实现背压（Backpressure）流式推送，单节点仅需少量底层 Netty Worker 线程即可维持上万个空闲长连接，避免传统 Tomcat 线程模型下“一连接一线程”导致的线程池耗尽（OOM）。

### 2. 多智能体 Tool Calling 与大模型多轮调用的延迟优化：
- **落地手段**：
  1. **过敏史与高频慢病就诊特征前置预加载**：使用 Redis Hash 将当前候诊患者过敏史预热，避免大模型首轮推理时盲目多次触发同步 SQL 查询。
  2. **会话记忆窗口剪枝**：`MessageChatMemoryAdvisor` 配置滑动窗口（仅保留最近 10 轮历史），减少单次 Prompt Token 开销达 40% 以上，显著降低首字呈现延迟（TTFT）。
